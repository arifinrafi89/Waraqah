# Each feature owns its domain model; `home` stops being a shared warehouse

Status: accepted

`Post`, `Profile` and `P2pListing`, along with their repository interfaces, dummy implementations and Riverpod providers, used to live under `features/home/` even though `home` only consumed them for its dashboard strips — the real owners were `book_bites`, `profile`/`core` and `p2p`. This meant 19 imports across three other features reached into `home`, seven of them into `home/presentation/controllers/home_controller.dart`, a presentation-layer file, to get data that had nothing to do with home's own UI. Repository wiring (`postRepositoryProvider`, `profileRepositoryProvider`, `p2pListingRepositoryProvider`, and separately `orderRepositoryProvider`) was also declared in presentation controllers instead of each feature's data layer, unlike the established pattern in `core/providers/book_providers.dart`.

`Post` moved to `features/book_bites/domain/`, `P2pListing` to `features/p2p/domain/`, and `Profile` — used by four features — to `core/models/`, alongside `Book`. Each feature's repository provider and derived providers moved into that feature's own `data/` layer (`book_bites/data/book_bites_providers.dart`, `p2p/data/p2p_providers.dart`, `orders/data/order_providers.dart`), and the profile equivalents moved into `core/providers/profile_providers.dart`. No class, field, enum or provider was renamed. The demo current-user id, previously duplicated as `profile-1` in three separate files, is now the single `currentProfileId` constant in `core/providers/profile_providers.dart`.

Trade-off: `home` and `profile` now import from `p2p` and `book_bites` (as composition surfaces displaying those features' content), so those two features are no longer importable in total isolation from every other feature. Accepted because the dependency now points from consumer to owner instead of the reverse — a feature's domain can be found where the feature lives, and deleting or rewriting `home` no longer breaks three unrelated modules.
